# 任務規劃規則

Applies To: `/tasks` 產出的 `specs/plans/NNN-<slug>/tasks.md`。

## Rule 1 - 驗收完成條件與關卡依賴須可判定

- Level: `MUST`
- 驗收任務須指出對應的驗收來源、通過條件與所需證據。可直接引用涵蓋該結果的既有驗證。
- 需人工確認的關卡須明列確認者或角色、需確認的版本與範圍，以及依賴該確認才能繼續的任務。

### Good Example

```md
- T010 自動回歸。來源為分類分析的讀取與錯誤案例。對待驗產品版本執行既有案例，全部通過後保存結果。
- T011 產品人工驗收。由使用者在指定的產品版本確認分類圖表的桌機版面及鍵盤焦點，保存確認紀錄。T012 回填 UI 基準依賴 T011。
```

### Bad Example

```md
- 自動回歸通過便勾選 UI 驗收並回填基準，人工驗收待日後補記。
```
