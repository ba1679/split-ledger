# UI 設計交接規則

Applies To: `/ui-plan` 產出的 `specs/plans/NNN-<slug>/ui/ui-plan.md`。

## Rule 1 - 設計確認須對應版本與範圍

- Level: `MUST`
- 交接文件須指出沿用的現況依據、本次變更的設計，以及仍待確認的畫面、狀態或互動。
- 已確認的設計須能追溯到固定設計版本、確認涵蓋的畫面與狀態，以及確認紀錄。部分確認時，須分別標明已確認與待確認的範圍。

### Good Example

```md
- 沿用固定現況基準的垃圾桶清單。
- 設計 v3 的永久刪除對話框已確認，範圍含文案、按鈕順序與預設焦點，附確認回覆連結。
- 刪除成功後的焦點落點待確認。
```

### Bad Example

```md
- 垃圾桶設計已確認，請參考最新版。
```

## Rule 2 - 互動決策須回寫到對應的畫面或行為註記

- Level: `MUST`
- 已確認且影響實作或驗收的互動決策，須記錄在對應的畫面或行為註記，並保留適用條件與待決事項。
- 若使用原型協助確認，交接文件須記錄原型要回答的問題、涵蓋的畫面與狀態，以及影響判讀的模擬限制。

### Good Example

```md
- 問題：用鍵盤永久刪除後，焦點應回到哪裡？
- 已確認並回寫垃圾桶的行為註記：刪除成功後，焦點移到下一筆的操作按鈕。若清單已空，焦點移到空狀態標題。
- 原型只模擬成功回應，刪除失敗後的焦點待確認。
```

### Bad Example

```md
- 鍵盤互動已定案，請開 prototype 看焦點怎麼移動。
```
