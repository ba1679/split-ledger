# API 契約規則

Applies To: `/api-plan` 維護的 `specs/truth/contracts/**` OpenAPI 契約。

## Rule 1 - API 契約須明定存取條件與拒絕語意

- Level: `MUST`
- 操作若受權限、資源歸屬或生命週期限制，契約須交代各項適用條件，以及拒絕時的 HTTP 狀態與適用的錯誤代碼。
- 契約須明定呼叫端有權辨識的資源狀態。當資源存在或處於何種狀態都屬受保護資訊時，拒絕回應須避免揭露該資訊。

### Good Example

```md
- 僅旅行擁有者可讀取使用中旅行的分類統計。
- 本人旅行在垃圾桶時回 409 TRIP_TRASHED。旅行不存在或不屬於目前帳號時，一律回 404 NOT_FOUND。
```

### Bad Example

```md
- 讀取旅行分類統計須登入。其他存取條件及錯誤回應由實作決定。
```

## Rule 2 - 有重複生效風險的寫入須定義結果查證與重送條件

- Level: `MUST`
- 寫入若可能在回應遺失後因重送而重複生效，契約須說明如何識別並查證原操作，以及查無結果時呼叫端能得出什麼結論。
- 契約須明定可安全重送的條件，或明定禁止重送。查證若同時回傳資源現況，契約須區分原操作結果與當前狀態。

### Good Example

```md
- 依旅行 ID 與操作 ID 查證移入垃圾桶命令。收據記錄原操作成功，旅行現況可顯示已復原。
- 查無收據時結果仍待確認。同一操作 ID 與相同請求重送時，若已有收據，回傳原結果且不再次寫入。
```

### Bad Example

```md
- 移入垃圾桶回應逾時時，查旅行目前狀態。若旅行仍可用，就視為上次失敗並以新操作 ID 重送。
```
