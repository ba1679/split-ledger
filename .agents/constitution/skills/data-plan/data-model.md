# 資料模型規則

Applies To: `/data-plan` 維護的 `specs/truth/data/data-model.dbml`。

## Rule 1 - 來源紀錄與衍生資料須可辨識

- Level: `MUST`
- 資料模型須區分作為依據的來源紀錄與由它推導的結果。
- 對受變更影響的衍生資料，須交代來源、涵蓋範圍及重建方式。若保存衍生資料，須交代更新時機，以及如何維持與來源資料的一致性。

### Good Example

```md
- 分類統計由同一趟旅行的支出、分攤與分類資料重建，涵蓋整趟旅行並依幣別計算。
- 支出、分攤與分類從同一份一致快照讀取，清單分頁不影響統計範圍。
```

### Bad Example

```md
- 保存各分類的統計金額，來源和更新條件由實作決定。
```

## Rule 2 - 模型變更須交代既有資料的對應與保留範圍

- Level: `MUST`
- 變更若影響既有資料，資料模型須說明舊資料如何對應到新模型，以及哪些帳務事實與歷史關聯須保留。
- 如有預期改變的既有行為，資料模型須指出變更範圍並引用已確認的需求。

### Good Example

```md
- 舊個人支出對應為旅行擁有者付款且僅由擁有者分攤。
- 保留原金額、幣別、分類關聯與日期。升級前後的個人支出統計一致。
```

### Bad Example

```md
- 舊支出直接遷入新表，付款人與分攤者欄位以預設值補齊。
```
