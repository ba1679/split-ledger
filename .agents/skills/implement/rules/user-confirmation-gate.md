# Rule 1 - 明確確認不得自行代替

- Level: `MUST`
- `[USER-CONFIRM]` 前置成果及證據備妥後，向指定使用者展示並請其依關卡通過條件確認；未收到明確確認前保持 `[ ]`，不得推定同意或自行勾選。
- 使用者要求修正時，依回饋修正並重新展示；明確確認後記錄確認及對應成果的可追溯證據，才回寫 `[X]`。
- UI 設計確認須核對共用契約所定版本、範圍及原回覆；設計意圖變更後重新確認，不能沿用舊版本批准。
- 未通過的關卡阻擋其依賴任務；其他不受阻且已解鎖的任務仍可執行。沒有其他可執行任務時回報等待與受阻範圍。

## Good Example

- 先展示並等待，再解鎖依賴。

```md
T011 展示示範成果；使用者確認後記錄並勾選，才執行依賴 T011 的 T012。
```

## Bad Example

- 以沉默代替確認。

```md
T011 展示後無回覆，假定同意並開始 T012。
```
