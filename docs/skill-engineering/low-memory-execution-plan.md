# Skill 工程編排提案

## 任務資訊

- 處理路徑：優化既有 skill。
- 改動範圍：跨 skill 的步驟與執行控制重寫。
- 目標 Skills：`implement`、`bdd`。
- 分支：`codex/low-memory-skill-mode`。
- 根因確認：使用者已確認資源累積與派工控制缺口，並要求繼續編排與實作。

## 控制平面重建

兩個入口讀取同一份一般參照文件 `.agents/skills/shared/low-memory-execution.md`，建立或承接資源契約。16 GiB 以下、明確指定或容量未知時採低記憶體模式。主代理直接實作與執行測試，最多一個固定輔助代理做獨立審查；skill 呼叫不等於建立新 agent。

`Parallel Hint` 保留批次 review 範圍，在低記憶體模式逐筆驗證及回寫。測試 worker 一個，瀏覽器依序跑；檢查點不通過時先回收並保存續跑資訊。工具無關閉能力時如實記錄限制，不假裝已回收。

## 檔案動作

### 新增 / 更新

- 更新兩個 `SKILL.md`。
- 新增共用一般參照文件 `shared/low-memory-execution.md`；不新增第三個可執行 skill、常駐監控或重複政策。
- 更新 implement 的任務選取、嚴格單步、平行派工、BDD 委派、停止與完成定義規則，清除衝突條款。
- 本文件保存編排與驗證結果；使用英文檔名，內容以繁體中文為主。

### 刪除

替換「無條件一次派出 Hint 所有代理」、「每筆獨立新建代理」、「focused tests 強制再開代理」的要求，保留批次審查、單筆驗證與完整回歸。原有有效規則檔繼續掛接，沒有需要刪除的整個檔案。

## 驗證方式

- 引用盤點、共用文件相對路徑解析、SOP／Rule 結構與格式、Git diff 檢查。
- 以代表性任務重演：16GB Hint 逐筆處理、單獨 bdd、不同作者審查、工具不能回收、程序持續累積、雙瀏覽器完整矩陣、執行中止與恢復。
- 一個未參與實作的審查者檢查 diff 與反例；不啟動巢狀代理或瀏覽器負載測試。
- 本輪只改 skill 文件，不執行與改動無關的產品全套測試，也不宣稱已實測解決工具內部記憶體洩漏。未來產品交付仍須實跑原完整回歸。

## 驗證結果

### 靜態檢查

- 引用分析器檢查兩個 skill：沒有缺失引用或孤立規則；另外解析兩個 `../shared/low-memory-execution.md`，確認指向同一份存在的文件。

- 使用專案 Node 24 wrapper 執行針對性 Prettier 檢查，明確覆寫專案原本忽略 Markdown 的設定；另檢查 `git diff --check`。
- 檢查輸出保存在忽略的 `.cache/low-memory-skill-validation/`；本輪沒有修改產品、測試或 runner 設定。

### 流程重演

以下是文件規則的人工情境推演，不是記憶體壓力實測。

| 情境                                | 核對結果                                                                                 |
| ----------------------------------- | ---------------------------------------------------------------------------------------- |
| 100 筆 DSL Hint                     | 主代理實作、一個固定獨立審查者；逐筆驗證立即回寫，整批完成才 review，不建立 100 個代理。 |
| 單獨執行 bdd／RAM 未知              | 建立低記憶體契約，限定指定入口與範圍，直接使用 runner；worker 一個，瀏覽器依序執行。     |
| 唯一輔助代理曾實作受審改動          | 不能自審或多加一個常駐代理；先證明釋放再替換，無法釋放則保存進度並回報。                 |
| 完成或 interrupt 後 REPL 仍持續增加 | 不算回收成功，停止新派工與重型工作，核對程序與工具關閉能力。                             |
| 無量測權限或無關閉 API              | 明列未知與能力限制，保留硬上限；不能確認工作結束時保存續跑點，不以全域 kill 處理。       |
| 12 Examples × 2 瀏覽器              | 24 個執行項目依序覆蓋；任一失敗、中止、跳過或未跑均不能宣稱完整回歸成功。                |
| 標準模式 Hint 分波                  | 先有有限預算，遵守依賴、逐筆驗證與整批 review gate。                                     |
| 已驗證 T012 後資源受阻              | T012 可保留 [X]、T013 未完成；恢復時核對版本、環境、證據與資源，再續跑。                 |
| Green 與 Refactor                   | 各自單一 requested step，不因重用代理而合併兩個入口。                                    |

### 獨立審查

由未參與實作的固定審查者 `/root/low_memory_review` 只讀檢查 diff、規則引用與上述情境；沒有新增巢狀代理、執行產品測試或瀏覽器負載。

首輪指出兩項問題：舊規則無條件要求單筆、與標準模式批次衝突；舊範例將回寫延至整批完成。實作者已限定單筆規則適用情境，並將範例改為逐筆驗證立即回寫、最後獨立 review。同一位審查者複查通過，沒有剩餘 findings。

### 驗證界限

本次驗證 skill 文件與控制流程，沒有進行長時間壓力測試，也沒有修改或證明修復 Codex 工具內部程序生命週期問題。後續執行產品 task 時仍須實跑每筆 Test Scope、獨立審查與完整交付回歸；資源不足只能延期未完成項目，不能降低完成判準。
