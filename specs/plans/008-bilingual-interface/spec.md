# 功能規格：繁中文案調整與英文介面

**功能分支**: `008-bilingual-interface`

**建立日期**: 2026-11-23

**狀態**: 草稿

**輸入**: 使用者希望調整中文用詞並支援英文版，兩個使用者故事共用一份 spec。使用者確認英文涵蓋旅帳自有 Web 介面全站。初次開啟時，只有瀏覽器偏好是中文才顯示繁中，其他情況顯示英文。手動選擇由同一瀏覽器記住。

## 範圍

- 繁中文案先收斂記帳、分攤、結算與還款流程的核心用詞，以及其他畫面引用同一概念的地方。同行者頁一併精簡指定說明。
- 英文涵蓋旅帳自有的公開及登入後 Web 介面，包括登入、帳本與旅行管理、垃圾桶、支出、成員、分類、分類分析、分攤、結算與還款，也涵蓋全站共用操作與狀態。
- 外部登入供應商控制的頁面及帳號跨裝置同步在本版範圍外。

## 使用者情境與測試 *(必填)*

### 使用者故事 1 - 用一致的繁中用詞理解帳務與下一步 (Priority: P1)

作為使用繁中記帳的使用者，我希望在記帳、分攤、結算和還款時看得懂每筆金額代表什麼，也能辨識每個操作的結果，以便正確記錄支出與付款。

**為何為此優先級**: 四個流程共用帳務概念。先確認使用者看得懂各概念和動作，英文版就能沿用同一套語意。

**獨立驗證方式**: 單獨以繁中介面操作一筆多人分攤支出，依序檢查結算金額、部分還款及相關結果訊息。

**驗收情境**:

1. **Given** 一筆多人分攤支出已入帳，**When** 使用者查看支出明細和結算，**Then** 各處對相同帳務概念使用一致的繁中稱呼，使用者可區分成員分攤金額與結算應付金額。
2. **Given** 一筆應付款已有部分還款，**When** 使用者查看還款紀錄與最新應付狀態，**Then** 文案可區分實付、剩餘應付及結清結果，對應的操作文字說明要執行的動作。
3. **Given** 使用者送出一筆還款紀錄，**When** 旅帳收到明確失敗，**Then** 介面顯示原因及下一步。
4. **Given** 使用者送出一筆還款紀錄且結果待確認，**When** 旅帳偵測到目前離線，**Then** 介面顯示「儲存結果待確認」，並提示「請檢查網路連線，連線後再查看結果」。
5. **Given** 使用者送出一筆還款紀錄，**When** 旅帳尚未能確認這筆紀錄是否已儲存，且未偵測到離線，**Then** 介面顯示「儲存結果待確認」及「查看結果」，供使用者查詢原本那一筆。
6. **Given** 某位同行者在 TWD 的淨額為零，且沒有涉及他的 TWD 待付項目，**When** 使用者查看帳本及結算，**Then** 該同行者的 TWD 狀態在兩處都用「已結清」。如果某幣別的應收與應付剛好抵銷，但仍有涉及該同行者的待付項目，兩處都用「淨額為零」，待付項目仍可查看。
7. **Given** 旅行所有幣別都沒有待付項目，**When** 使用者查看結算，**Then** 「待付款」區只顯示一則全旅行空狀態。
8. **Given** 旅行已有同行者，**When** 使用者查看同行者頁並嘗試新增名稱重複的同行者，**Then** 兩段指定說明均省略，送出時仍提示名稱已使用。

**功能需求（FR）**:

- **FR-001**: 系統 MUST 在記帳、分攤、結算、還款及其他引用同一帳務概念的繁中介面，使用一致的核心詞彙。「分帳」描述整體流程，「分攤」描述一筆支出如何拆給各人。結算頁用「應付金額」及「已付金額」區別應付與已記錄的實際付款，並保留結清狀態的語意。
- **FR-002**: 系統 MUST 採用台灣繁中常用且清楚的動作及狀態文案。帳本入口可用「記一筆」，金額欄位用清楚的名稱，例如「支出金額」。儲存結果待確認時，採「儲存結果待確認」及「查看結果」，偵測到離線時補充檢查網路與恢復連線後的下一步。查看結果只查詢原操作的狀態。
- **FR-008**: 帳本及結算依同行者與幣別顯示狀態。淨額為零且目前付款安排中沒有涉及該同行者的待付項目時，顯示「已結清」。淨額為零但仍有涉及該同行者的待付項目時，顯示「淨額為零」。結算區標題採「待付款」。只有部分幣別沒有待付項目時，各該幣別顯示如「TWD 無待付款項」，其餘幣別繼續顯示待付明細。全旅行沒有待付項目時只顯示「目前沒有待付款項。」一次。
- **FR-009**: 同行者頁移除「同行者不用登入，由你統一管理這趟旅行的帳務。」及名稱欄下方的說明「前後空白會自動去除；同一趟旅行內名稱不可重複。」同一旅行的名稱驗證、去除前後空白及實際欄位錯誤提示依原規則執行。

### 使用者故事 2 - 以英文操作整個旅帳 (Priority: P2)

作為偏好英文的使用者，我希望從第一次開啟旅帳就能看懂介面，並用英文完成登入、記帳、結算及管理操作，以便持續使用同一份帳本。

**為何為此優先級**: 英文介面擴大可使用旅帳的對象，並沿用繁中文案調整所釐清的帳務概念。

**獨立驗證方式**: 用尚無手動語言偏好的瀏覽器驗證首次顯示語言，以英文操作全站代表流程，再切換兩種語言並重新開啟確認偏好。

**驗收情境**:

1. **Given** 瀏覽器沒有旅帳的手動語言偏好，**When** 分別以中文（例如 `zh-TW`、`zh-CN`）、英文、其他語言（例如日文）及無可辨識偏好首次開啟旅帳登入頁，**Then** 兩種中文案例均顯示繁中，其餘案例均顯示英文。
2. **Given** 瀏覽器語言首選為日文、第二順位為中文，且使用者尚未手動切換，**When** 使用者直接開啟旅帳頁面，**Then** 頁面採英文。
3. **Given** 使用者的瀏覽器首選中文且旅帳目前顯示繁中，**When** 使用者在登入前手動選擇英文，**Then** 登入畫面切換為英文，登入後導覽、重整及以同一瀏覽器再次造訪時都沿用英文。
4. **Given** 使用者已登入並以英文瀏覽一趟旅行，**When** 切換成繁中並繼續瀏覽，**Then** 介面以繁中呈現同一趟旅行，再次開啟時沿用最新選擇。
5. **Given** 旅帳以英文顯示，**When** 驗收者操作登入、旅行管理、垃圾桶、支出、成員、分類、分類分析、分攤、結算與還款，**Then** 各流程的旅帳自有文字、操作、狀態回饋與輔助工具文字皆為英文，且可完成既有操作。
6. **Given** 帳本包含使用者輸入的中文旅行名稱、成員名稱、分類名稱或支出項目，**When** 使用者切換到英文，**Then** 系統提供的標籤依英文呈現，畫面仍以原文顯示這些帳本內容。

**功能需求（FR）**:

- **FR-003**: 系統 MUST 以選定的繁中或英文呈現全站自有 Web 介面，包括導覽、標題、表單、對話框、日期選擇器的系統文字、圖表文字、空狀態、載入及操作結果、欄位驗證和錯誤訊息。英文文案 MUST 傳達對應的帳務概念、狀態與下一步。
- **FR-004**: 瀏覽器尚無有效的旅帳手動語言偏好時，系統 MUST 依瀏覽器排名第一的語言偏好決定介面語言。中文語言標籤一律顯示繁中，其他語言、缺少或無法辨識的偏好一律顯示英文。此規則適用於登入前及直接進入旅帳頁面。
- **FR-005**: 系統 MUST 讓使用者在登入前及登入後切換繁中與英文。手動選擇 MUST 優先於瀏覽器偏好，並在同一瀏覽器的頁面導覽、登入、登出、重整及再次造訪時保留。切換 MUST 維持當前瀏覽的頁面與資料範圍。
- **FR-006**: 系統 MUST 以原文顯示使用者輸入的旅行名稱、成員名稱、分類名稱與支出項目，並以當前語言顯示「未分類」等旅帳提供的介面文字。支出項目沿用現有欄位。

**非功能需求（NFR）**:

- **NFR-001**: 系統 MUST 讓輔助工具辨識目前頁面的語言，並以對應語言提供操作名稱與狀態訊息。語言選擇及既有主要流程 MUST 可用鍵盤操作，且手機版須能辨識並操作兩種語言下的主要控制項。

依使用者指示，008 的無障礙驗證延後。SC-002 本輪驗收涵蓋可見文案、手機與桌機的主要操作。輔助工具、鍵盤與焦點留待後續驗證。

### 邊界情況

- 已有手動選擇後，變更瀏覽器的語言順位仍沿用手動選擇。旅帳語言偏好被清除或無效時，按 FR-004 重新判定。
- 當寫入操作的結果尚待查證，跨語言切換後仍呈現同一個結果待確認狀態及既有查證操作。
- 同一畫面可同時包含英文介面文字與使用者輸入的中文名稱或支出項目，按 FR-006 驗收。

## 需求 *(必填)*

### 全域需求

- **FR-007**: 系統 MUST 在兩種語言與文案調整前後維持既有操作、權限、帳務規則及原始資料，包括幣別、原始金額、計算結果與精度。切換語言只更新介面語言偏好及呈現。

### 關鍵實體

- **介面語言偏好**。同一瀏覽器內的手動選擇，可為繁中、英文或尚未選擇。
- **帳務詞彙**。在支出、分攤、結算、還款及相關介面對應到同一帳務概念的名稱與操作用語。

### 預期 truth 變更

- **ADD**。新增全站英文、預設語言判定、手動切換及瀏覽器內偏好的驗收行為。
- **MODIFY**。更新相關前端規格的繁中用詞與自有介面文案的語言條件。

## 成功標準 *(必填)*

### 可量測成果

- **SC-001**: 繁中走查涵蓋記帳、分攤、結算與還款四個流程。經確認的核心詞彙在受影響介面一致，且明確失敗及結果待確認均能辨識狀態與下一步。
- **SC-002**: 全站盤點涵蓋範圍內各頁與狀態，其中旅帳自有的可見及輔助工具文字均有英文呈現，手機及桌機可完成對應主要操作。
- **SC-003**: 首次顯示的中文、英文、其他語言與無偏好四類案例皆依 FR-004 顯示。兩種手動設定各自通過導覽、登入／登出、重整及再次開啟的檢查。
- **SC-004**: 用同一份驗收資料切換繁中及英文，兩次走查顯示相同的原始帳務資料與計算結果，使用者輸入文字與原值相同。

## 假設

- 首次顯示所稱「瀏覽器偏好」以順位最高的語言解讀。中文包含各地區與文字變體（包括簡中與繁中），產品提供的中文介面為繁中。
- 其餘繁中與英文逐句定稿、語言入口位置，以及日期、金額與百分比的具體呈現樣式，留待文案及 UI 設計確認。驗收沿用既有的日期意義、幣別及金額精度。
