# 前端 / UI 與靜態雛形規劃：旅行分帳與結算

## 介面範圍

- 目標系統介面：旅行 owner 的同行者、支出、精確份額、結算及實付介面。
- 需求來源：本 plan 的使用者故事 1–5、FR-001–041、NFR-001–004；使用者已確認付款人私下決定實付額，UI 不選擇或記錄取整方法。
- 上游依據：`spec.md`、`research.md`、`plan.md` Wave 3、四份 acceptance feature、`truth-delta.md`；`specs/truth/contracts/` 的 trip/member/expense/settlement/repayment schema 與 group、`specs/truth/data/data-model.dbml`、既有前端 design system 和操作模式。
- 產出順序：本檔先定稿，之後製作 `ui/*.html` 與共用靜態資源。HTML 是產品雛形，不是實作或權威規格。

## 視覺方向

- 風格來源：沿用現有旅帳的米白背景、深綠動作、白色卡片、細邊線、襯線標題與桌面側欄。`ui-ux-pro-max` 的設計系統查詢作為可讀性與金融數值層級參考；既有產品視覺優先。
- 本次風格結論：像旅行手帳的清爽帳務介面；精確金額用等寬數字呈現，主要行動明確，說明文字節制。
- 視覺重點：旅行內的四個任務入口、成員身分及停用狀態、支出公平份額、分幣別餘額、付款安排與實付紀錄。
- 審美原則：只呈現 owner 真會看到的產品文字；不把資料結構、HTTP 狀態或 review 說明放入畫面。

## 畫面與流程

### 1. 旅行帳本入口 — `ui/index.html`

- 目的：保留原始支出總額與沿途花費，加入「同行者」及「結算」入口；顯示個人支出與共同支出的差別。
- 進入：owner 已登入自己的旅行；其他帳號與同行者不取得此頁資料。
- 操作：查看分幣別原始花費，新增支出，切到同行者或結算，進入既有支出編修。
- 成功：從旅行帳本到 `members.html`、`expense.html` 或 `settlement.html`。
- 失敗：載入失敗保留回程路徑與重試；無支出時提供「記錄第一筆支出」。

### 2. 同行者 — `ui/members.html`

- 目的：顯示 owner 與同行者，新增、改名、停用、重新啟用及僅未被引用者可刪除。
- 操作：在頁面內以表單新增或改名；停用與刪除先說明影響再確認。owner 列固定、不可編輯。歷史引用者的刪除要求改為停用。
- 成功：名單更新，同行者歷史身分與帳務仍保留；停用者不進入新支出的選取清單。
- 失敗：空名、trim 後同名（含 owner/停用成員、ASCII 英文不分大小寫）在欄位旁顯示；伺服器 `MEMBER_NAME_CONFLICT` 映射同訊息。結果未確認時保留輸入，以預留 ID 查證，不能顯示成功。

### 3. 記錄或編修支出 — `ui/expense.html`

- 目的：延續既有項目、金額、幣別、日期、分類欄位；加入恰好一位付款人及一位以上平均分攤者。預設 owner 付款且 owner 分攤，讓個人支出快速完成。
- 操作：可只選 Amy、Bob 分攤而由 owner 付款；人數變化即更新「每人平均」預覽。JPY 100 三人為 `JPY 33.333…（100 ÷ 3）`，並註明尚未取整。付款人無須參與分攤。
- 成功：保存後返回帳本並刷新結算；修改時完整替換該支出的分攤貢獻，已發生實付不被抹除。
- 失敗：付款人/分攤者缺漏、停用或跨旅行成員、金額/幣別/日期不合法時，就近顯示可修正訊息。結果不明保留草稿並查證，不樂觀更新帳本或餘額。

### 4. 結算 — `ui/settlement.html`

- 目的：依原始幣別顯示每人成員淨額與精確付款安排；旅行層級 Simplify Debts 開關可切換並保存。
- 操作：開關關閉顯示直接關係，開啟顯示後端建議關係與最多三句說明；顯示直接與建議筆數。分幣別卡片不能合成單一總額。可進入安排的實付結清或獨立還款。
- 成功：切換後讀取同一 `accountingRevision` 的新結算；原始支出、還款不被改寫。無變化時說明不需改道。無安排時呈現已平衡。
- 失敗：切換保存/重算失敗時維持上一個已確認的模式與安排並可重試；過期安排要求刷新。

### 5. 實付後按結清 — `ui/settle.html`

- 目的：針對特定安排輸入付款人實際交付的正數，按「結清這筆安排」。精確公平應付始終在旁顯示。
- 操作：顯示付款人、收款人、幣別、精確應付與日期；不預設付款人決定的實付金額，不提供取整方式選擇。任何幣別合法的正數實付可送出，包括比精確應付少或多。
- 成功：顯示不可變結清摘要、精確公平應付、實付與差額已納入結算；指定安排關閉，不因這次超付生成反向付款。其餘安排重算。
- 失敗：非正數/無效位數就近提示；`ACCOUNTING_REVISION_CONFLICT` 或 `ARRANGEMENT_NOT_FOUND` 不送出舊安排，返回刷新；網路結果不明以預留 settlement ID 查證，不自動重送或宣稱成功。

### 6. 獨立還款 — `ui/repayment.html`

- 目的：另行記錄付款人、收款人、幣別、金額及日期，支援部分與多次還款；此流程不關閉指定安排。
- 操作：若 Amy 應付 owner JPY 600，輸入 JPY 400 後保存並顯示剩餘 JPY 200；若輸入 JPY 700，先顯示超額 JPY 100 與 owner 將反向應付 Amy JPY 100，owner 再明確確認才送出。
- 成功：只重算該幣別；已保存還款保留實際付款事實。取消超額提示則不保存。
- 失敗：本人付本人、停用/異旅行成員、非正數與無效幣別就近提示。警告版本變動時刷新並重新顯示警告；結果不明以預留還款 ID 查證。

## 互動與假資料原則

- 雛形以「日本旅行」及 owner Alice、Amy、Bob 為主要假資料；另用 Carol 呈現 Simplify Debts 的改道例子。展示 JPY 100/3 的精確值、JPY 600/700 的獨立超額、JPY/TWD 分離。
- 雛形使用本地前端狀態模擬切頁、切換、驗證與結果，無伺服器寫入。操作需要回饋，不只是截圖。
- 同一範例在各頁面保持金額語意一致；不同示例（改道、循環份額、超額）以清楚區塊標示，不暗示它們是同一筆來源。

## 狀態與資訊揭露

- 顯示：owner/同行者名稱、啟用狀態、原始支出、付款人與分攤者、精確公平份額、分幣別淨額與安排、最多三句簡化說明、實付事實及結清狀態。
- 不顯示：同行者登入或共編入口、取整策略、伺服器 token/UUID、跨幣別合計、將循環小數作有限小數的假精度。
- 狀態：載入、空、有效、輸入錯誤、保存中、已保存、重算中、版本過期、結果未確認、讀取或保存失敗、超額待確認、已結清。靜態頁提供可操作的主路徑與關鍵錯誤演示。
- 角色：只有旅行 owner 可讀寫；前端的隱藏不是權限保護，API 必須按 truth 驗 owner。

## 驗證、無障礙與響應式

- 驗證：本地即時提示只協助輸入；權威衝突由 API 回覆重檢。金額依幣別實付位數輸入；精確公平份額不受該位數限制。
- 結果未明：保留草稿與預留 ID，提供「查證結果」及回到已確認資料的路徑。查證時 404 不能當作可安全重送的證明。
- 無障礙：語意化表單標籤、fieldset/legend、switch 的可讀狀態、欄位 `aria-describedby`、錯誤 `role=alert`、保存結果 `role=status`、可見焦點、原生鍵盤操作；精確值同時提供完整分數文字，不只省略號。
- 響應式：手機 375px 單欄、底部安全區留白、主要動作至少 44px；桌面維持左側導覽與較寬比較版面。卡片換行不橫向捲動，金額與成員名稱換行仍可辨認。

## 靜態雛形輸出規劃

- 入口：`ui/index.html` 為真實旅行帳本，不是 sitemap。
- 檔案：`index.html`、`members.html`、`expense.html`、`settlement.html`、`settle.html`、`repayment.html`，共用 `prototype.css`、`prototype.js`。
- 狀態檢視：各主頁可加 `?state=loading`、`?state=error` 或 `?state=unconfirmed` 查看載入、失敗或結果未確認的產品文案；一般互動則顯示欄位錯誤、超額待確認與成功結果。
- 換頁：旅行帳本到同行者/支出/結算；結算到結清或獨立還款；成功後返回結算。新增/改名、警告、錯誤在原頁顯示。
- Review：可由入口走完「建立成員→記共同支出→看精確分攤→切換簡化→輸入實付結清」，並可另走「部分還款→超額警告/取消/確認」。

## 前端實作切分建議

- 頁面容器：TripLedger、TripMembers、ExpenseEditor、TripSettlement、SettleArrangement、IndependentRepayment。路由均位於 owner 旅行之下。
- 共用 UI：原有 AppShell、Button、Input、DateField、QueryState、FormDialog；新增精確金額顯示、MemberPicker、CurrencyBalance、ArrangementCard、WriteOutcome。依共用憲法，通用控制採 shadcn/ui，帳務語意元件自建。
- API 依賴：trip 設定/revision、members CRUD、expense CRUD、`GET settlement`、`POST/GET settlements`、`POST/GET repayments`；精確值以 `ExactAmount` 分子/分母傳輸，實付 `MoneyAmount`。結清需傳安排 key、revision、精確應付快照；獨立超額需伺服器警告及確認快照。
- 驗收：精確份額與各幣別零和、改道不增筆數且不改來源、任意合法正數實付後關閉指定安排、獨立超額雙階段確認、歷史身分、結果不明不誤報，以及手機與鍵盤完成主流程。
