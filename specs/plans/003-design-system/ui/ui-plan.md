# 前端 / UI 與靜態雛形規劃

## 介面範圍

- 目標系統介面：`前端介面與共用設計系統`
- 需求來源：`spec.md` FR-001–FR-006、NFR-001–NFR-003、SC-001–SC-004；驗收旅程 `features/acceptance/design-system-migration.feature`。
- 上游依據：`plan.md` Wave 1、`research.md`、`truth-delta.md`、既有 `specs/truth/features/frontend/**` 及現行 React/CSS 實作。
- 產出順序：先完成本 UI plan，再建立可操作的 `index.html`。此雛形是規劃材料，不代表示範已實作或獲使用者確認。

## 視覺方向

- 風格來源：現行 `apps/web/src/styles.css` 與旅行清單、表單。米白背景、白色卡片、深綠文字與主按鈕、淺綠側欄、襯線點綴。
- 本次風格結論：保持既有外觀及流程；對齊色彩、字體、間距、圓角、邊框、焦點與圖示的共用語意值。先以現行值建立基準，差異由示範對照確認。
- 視覺重點：桌面側欄、手機底部導覽、旅行卡片、新增旅行表單及載入/錯誤/成功狀態。
- 審美原則：不套用元件庫預設視覺覆蓋品牌外觀；裝飾圖示保持一致線條，文字仍承擔主要資訊。

## 畫面與流程

### 1. `旅行清單及新增旅行示範`

- 對應雛形檔案：`ui/index.html`
- 主要目的：以一個完整互動區塊展示共用設計值、按鈕/卡片/對話框/欄位與圖示，作為第一階段審查基準。
- 進入條件：使用者已登入；假資料預載一筆旅行。雛形不處理真實登入。
- 主要操作：開啟新增旅行、輸入名稱及選填日期、驗證、取消或建立；載入及讀取錯誤可由雛形網址的 `?state=loading` 或 `?state=error` 檢視；讀取錯誤可重試。
- 成功流轉：建立後關閉表單、清單增加旅行卡片與成功訊息；可在同頁查看卡片。正式產品仍依現行 truth 導向旅行帳本。
- 失敗回饋：空名稱、無效日期與結束日早於開始日顯示欄位附近或表單內錯誤；讀取失敗顯示可重試訊息，且不顯示他人資料。

## 互動與假資料原則

- 假資料策略：固定一筆示範旅行及本地新增項；與真實帳號、API 和資料庫隔離。假資料不可誤表示為持久化結果。
- 互動原則：按鈕可點、表單可輸入、錯誤可修正、對話框可取消，鍵盤焦點清楚。雛形用單頁狀態切換避免新增產品路由；測試狀態透過網址參數載入，不在產品畫面增加審查控制項。
- 內容原則：維持現行畫面語氣與欄位名稱；雛形只顯示產品使用者會看到的內容。

## 狀態與資訊揭露

- 使用者可見資訊：旅行名稱、日期、支出數、載入/失敗/成功與表單驗證訊息。
- 必須隱藏資訊：其他帳號旅行、技術設定、設計 token 名稱、遷移進度與 reviewer 指示。
- 主要 UI 狀態：清單載入中、清單可用、清單空白、讀取失敗、表單待填、驗證失敗、儲存中、成功。示範雛形模擬其中主要狀態；實作驗證須涵蓋全部。
- 角色或權限差異：沿用既有已登入帳號隔離；本次不新增角色或權限。

## 驗證與錯誤回饋

- 輸入驗證：沿用旅行名稱必填、日期可選填、日期格式有效及結束日不得早於開始日的既有規則。
- 狀態衝突處理：儲存中避免重複提交；結果不明時沿用既有可理解訊息與查證流程，不在視覺遷移中改變帳務或保存語意。
- 使用者可理解錯誤訊息：保留 `role=alert` 等可宣告語意；訊息指出問題及下一步。焦點、對話框關閉與返回操作應按原流程驗證。

## 靜態雛形輸出規劃

- 多頁入口：本示範為單頁流程，以 `ui/index.html` 為入口；對話框與狀態在頁內切換。
- 預計輸出檔案：`ui/ui-plan.md`、`ui/index.html`。
- 換頁原則：正式路由保持現況；雛形展示旅行清單到新增旅行及結果的完整流轉，不新增假路由。
- Review 目標：讓使用者評估保留外觀的方向、共用元件質感與圖示相似度，再決定是否進入其餘範圍實作。

## 前端實作切分建議

- 頁面 / 容器切分：示範優先考慮 `Trips` + `TripForm` + `AppShell` 中的必要樣式；其餘登入、旅行詳情、支出與分類待示範確認後遷移。
- 共用元件或區塊：語意設計值、按鈕、卡片、欄位、對話框、狀態提示、導覽與圖示映射。保留日期選擇器現有互動契約，逐項評估是否需要替換。
- 對後端契約的依賴：沿用 `specs/truth/contracts/**`，本次無新增或變更 API/data 契約；UI 視覺回歸對照既有 frontend feature truth。
- 驗收重點：桌面與手機、鍵盤與焦點、輔助工具語意、載入成功失敗、帳號隔離、現有記帳流程。實作示範得到使用者確認之前，後續畫面不開始遷移。
