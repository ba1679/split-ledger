# 前端 / UI 與靜態雛形規劃

## 介面範圍

- 目標系統介面：Phase 1A 個人旅行記帳的響應式 Web 介面。
- 需求來源：本 plan 的 spec.md、三份 acceptance feature files、research.md、truth-delta.md，以及 specs/truth/techstack.md。
- 產出順序：先建立本文件，再依畫面與流程產出 HTML、CSS 與靜態互動。
- 上游補充：plan.md 已建立；本輪承接 system-analysis 的 Wave 1 已核可 UI 基準，Wave 4 已完成 API/data 規劃對齊（見文末）。UI 不修改 truth。

## 視覺方向

- 暫用產品名稱「旅帳 / TRAVEL LEDGER」，僅為雛形標示，非已確認品牌。
- 以旅行手帳為方向：暖白背景、墨綠主色、深色數字、細線邊框、克制的圓角；將幣別與金額置於最高資訊層級，不使用跨幣別的單一總額。
- 字體使用系統繁中字體與 sans-serif，數字等寬排列；不依賴遠端字體或圖片。
- ui-ux-pro-max 的兩次設計系統搜尋結果偏向行銷版型、極光/玻璃效果，未直接適用於記帳工具，因此不採用或封存該輸出。視覺採人工判斷；互動沿用 skill 的鍵盤、自動完成、表單與觸控建議。
- 色彩 token：背景 #f6f6f0、面板 #ffffff、文字 #192e29、次要文字 #5b6b64、主色 #245c49、危險 #a83232、邊框 #dce3dc。使用者已於 2026-11-05 核可目前設計，包含自訂日期選擇器。

## 畫面與流程

### 1. 登入入口

- 對應雛形：index.html。
- 目的：以 Google 登入個人帳本。
- 操作及成功流轉：Google 按鈕顯示等待狀態，進入 trips.html；雛形只模擬登入，不連接 Google。
- 失敗：index.html?state=error 呈現登入失敗，提供重試；未成功前不顯示帳本資料。

### 2. 我的旅行

- 對應雛形：trips.html。
- 目的：瀏覽自己的旅程，建立新帳本。
- 操作：點擊旅行卡進入明細；「新增旅行」開啟含名稱與選填開始/結束日的 dialog。名稱未填與日期反序均原處提示；各自選填。成功後進入新旅行的空帳本。
- 狀態：有資料、空清單、載入及讀取失敗；日期缺一端以「開始日未定 / 結束日未定」顯示。

### 3. 旅行帳本

- 對應雛形：trip.html?id=…。
- 目的：查看支出紀錄與分幣別總額，快速新增及修改。
- 操作：新增支出 → expense.html；點擊支出 → 編輯；「旅行日期」可補填日期。金額摘要逐幣別顯示 ISO 代碼，不混加。
- 結果：新增/修改後返回此頁，顯示保存成功回饋及更新後清單與總額；刪除前開啟確認 dialog。
- 失敗：讀取失敗或離線時保留可理解的重試入口；不將失敗當成功；trip.html?state=error/offline 可 review。

### 4. 新增 / 修改支出

- 對應雛形：expense.html?trip=…；編輯另帶 expense=…。
- 必填：項目、金額、幣別、日期；分類選填。日期取裝置當地日期，不使用 UTC 日期截取。
- 幣別為可搜尋的 combobox，顯示代碼與名稱；鍵盤上下移動、Enter 選取、Escape 關閉。搜尋文字本身不構成選定幣別。分類也可搜尋，選項含「未分類」。
- 輸入即時阻擋：負號、JPY 與 TWD 小數點及超出所選幣別位數的輸入；貼上不合法的整筆金額時拒絕整次貼上，保留原值並提示，不刪字符後當另一金額保存。支援保留輸入過程的空值及尾端小數點，保存前要求有效正數。
- 變更幣別：若原金額不符合新幣別位數，不四捨五入，顯示提示並要求手動修正後再保存。
- 預設分類：取此裝置上次選擇且仍可用的分類；沒有可用紀錄則未分類。雛形記憶可用分類識別，不以名稱記憶，改名後仍正確。正式版按帳號隔離，登入/登出需清快取。
- 保存中防止重複提交；成功回明細；失敗保留表單，提示再試。取消回原旅行。刪除對話框確認項目/金額，不提供未定義的復原功能。

### 5. 分類管理

- 對應雛形：categories.html。
- 目的：建立、改名與刪除跨旅行共用的分類。
- 列表顯示名稱、使用筆數與操作；新增/改名以 dialog 輸入。使用中分類仍有可按的刪除入口，明確解釋阻擋原因；不默默禁用。未使用的分類經確認可刪除。
- 改名後跨旅行顯示新名稱；從支出編輯可清除分類關聯。2026-11-05 已確認建立/改名皆去除前後空白，非空、最多 30 個字，同帳號不可重名且英文不分大小寫。欄位提示「分類名稱最多 30 個字」或「已有相同名稱的分類」，失敗保留草稿；目前 HTML 雛形尚未同步這項新規則，正式 API 與資料庫亦須驗證。

## 互動與假資料原則

- 雛形含兩趟旅行及多幣別支出，保存在獨立命名的 sessionStorage，僅供同一瀏覽器 review 互動，非正式跨裝置保存。
- 「上次分類」依需求使用獨立命名的 localStorage，不讀寫既有應用資料；其他資料僅為假資料，不含 Google 帳號或真實支出。
- 幣別清單使用研究已核對之 SIX 快照，僅用於本雛形；正式執行期仍需 Setup 封存與測試。金額假資料運算亦採 BigInt 整數，避免展示錯誤的加總。
- 所有 HTML 只放產品內容；review 操作方式與局限記錄在本文件。

## 狀態與資訊揭露

- 個人帳本，不呈現「邀請旅伴」「分帳」「退款」入口。
- 操作成功提供 aria-live 回饋；讀取中顯示載入文字；空白帳本引導新增支出。
- 雛形可用 query 參數 state=error / offline / loading 切換旅行列表或明細狀態；入口 state=error 查看登入失敗。這些開關不放入產品主流程。
- 正式版 session 過期應返回登入；雛形不驗證真實身分。所有後端擁有者/權限仍由正式 API 保證。

## 驗證與錯誤回饋

- 錯誤訊息緊鄰欄位，保存失敗保留輸入；不能只用顏色提示。
- 原生 dialog 支援 Escape、焦點限制與關閉後焦點恢復；可見標籤、焦點外框、觸控目標至少 44px。
- 螢幕寬 375/768/1440px：手機改單欄、底部主導航、表單全寬，主要動作不遮蓋內容。金額長字串可換行，不以頁面水平捲動處理。
- 尊重 reduced-motion；不使用只靠 hover 才能找到的操作。

## 靜態雛形輸出規劃

- index.html 是產品登入入口，非檔案目錄。
- trips.html、trip.html、expense.html、categories.html、styles.css、app.js、currencies.js、date-picker.css、date-picker.js。
- 主流程：登入 → 旅行清單 → 建立/選擇旅行 → 新增支出 → 查看各幣別總額 → 修改/刪除；分類管理可從導航進入。
- 對應驗收：登入與日期對應第一份 feature；支出、統計與輸入驗證對應第二份；分類管理與預設對應第三份。

## API/data 對齊與實作 handoff（2026-11-05）

Handoff：plan package `specs/plans/001-personal-travel-expenses`、truth root `specs/truth`、truth delta `specs/plans/001-personal-travel-expenses/truth-delta.md`；介面為「旅行記帳前端介面」，承接 plan Wave 4。已讀 `/api-plan` 8 個 ADD 與 `/data-plan` 9 個 ADD；本節是規劃核對，不表示 HTML 已連接真實 API。

| UI 責任 | 契約依據 | 前端承接要點 |
| --- | --- | --- |
| Google 登入、登出、帳號隔離 | Better Auth `/api/auth/*`、`GET /api/me` | 框架處理 OAuth；依真實 session 顯示帳本。登出/換帳號取消並清除舊查詢，localStorage 分類偏好以 user id 分隔。 |
| 旅行清單、建立及日期補填 | `GET/POST /api/trips`、`GET/PATCH /api/trips/{tripId}` | `expenseCount` 為全帳本筆數；起迄日 null 為未設定，PATCH 省略不變、null 清除。旅行卡的地名裝飾是假資料，不新增目的地欄位。 |
| 支出新增、查看、修改、刪除 | `/api/trips/{tripId}/expenses` 及 `/{expenseId}` | 金額以大單位字串送出，不經 Number。以回應的歷史 minorUnit 顯示及驗證原幣別；換成其他幣別才套用目前目錄位數。分類 null 表示未分類。 |
| 幣別統計與列表筆數 | `GET /api/trips/{tripId}/totals`、`ExpenseList.totalCount` | 總額由後端提供，不用目前載入頁面試算全帳本；跨頁支出以 cursor 載入更多。無支出時 totals 為空陣列。 |
| 分類建立、改名、刪除與筆數 | `GET/POST /api/categories`、`GET/PATCH/DELETE /api/categories/{categoryId}` | 使用 usageCount 呈現筆數；以 409 區分使用中不可刪與名稱重複，保留草稿。前端先提示 30 字/重名，伺服器仍為權威。 |
| 幣別自動完成 | `GET /api/currencies` | 以固定清單的 code/name 搜尋與 minorUnit 限制輸入；TWD 另依產品規則只允許輸入整數（不改目錄的 ISO 位數）；請求失敗不使用猜測位數保存。 |

實作與 DSL 必須承接的行為：

- 支出 mutation 成功後使受影響支出、旅行筆數、各幣別總額與分類使用筆數失效；改名後也重新取得支出中的目前分類名稱。無需在客戶端另維護一份金額權威。
- 使用者明確選「未分類」時清除此帳號在此裝置的分類偏好；載入時只接受仍在本人分類清單的 id，不以名稱判斷。localStorage 不可用時仍允許記帳，只是不沿用裝置偏好。
- UUID 在該次建立前產生並保留。POST 回應遺失時以單筆 GET 查證，查到即以已保存處理；暫時查不到顯示「保存結果尚未確認，請重新整理確認」，保留草稿和原 UUID，不自動新增另一筆。明確尚未送出的離線情況才說尚未保存。PATCH/DELETE 結果不明也先重新查詢，mutation 不盲目重試。
- 400 顯示欄位錯誤；401 回登入並清除舊帳號顯示；404 提供返回帳本/清單；409 依 code 顯示可理解原因；Origin 驗證拒絕依 API 契約提示重新整理，不當成保存成功。寫入傳 application/json，依同 origin 夾帶 session，不能把 owner id 放入 payload。
- 分頁、裝置偏好、未知結果與約束衝突要有對應的介面級驗收；這些是原有記帳流程的資料一致性邊界，不增加共同編輯功能。

## 設計回推 HTML 與驗證紀錄（2026-11-05）

- 使用者要求先同步設計稿，本輪只更新靜態雛形；未改動 .pen 或 API/data truth。
